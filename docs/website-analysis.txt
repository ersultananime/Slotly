Анализ сайта компании

Пользовательский сценарий
1. В /dashboard вставить адрес сайта, можно без https://.
2. Нажать «Подготовить базу знаний».
3. Проверить черновик и просмотренные источники.
4. Нажать «Использовать это описание» (или «Заменить текст в редакторе»).
5. При необходимости отредактировать, нажать «Сохранить и получить код виджета».
Черновик не записывается в Supabase до сохранения. Ручное заполнение доступно без анализа.

Настройка перед запуском
- Применить предыдущую миграцию 0002_dashboard.sql, если ещё не применена.
- Применить supabase/migrations/0003_website_analysis_quota.sql в Supabase SQL Editor.
- Добавить GEMINI_API_KEY в переменные окружения сервера/Vercel, без префикса NEXT_PUBLIC_.
- Не передавать ключ клиентам, не хранить в Git. Локально использовать .env.local.
- При необходимости задать GEMINI_WEBSITE_MODEL (по умолчанию gemini-2.5-flash).
- Перезапустить сервер или выполнить новый deployment после изменения переменных.
- Хостинг должен разрешать Node.js DNS/HTTP/HTTPS и запросы длительностью до 90 секунд.

Поведение и ограничения
- До 5 HTML-страниц: исходная и до 4 страниц услуг, цен, FAQ, контактов, о компании.
- Дополнительные страницы и их редиректы остаются в пределах origin исходной страницы после перенаправлений.
- До 2 MB на страницу и 14 000 символов текста на страницу.
- Загрузка страниц ограничена 25 секундами, AI запрос — 45 секундами.
- Не выполняется JavaScript сайта, не читаются PDF и страницы за авторизацией.
- Частичный результат помечается, источники доступны для проверки пользователем.
- Каждая попытка расходует квоту: не чаще раза в минуту, до 10 попыток в час на пользователя.
- Квота хранится в Supabase, работает между инстансами и при конкурентных запросах.
- Без ключа или миграции анализ показывает сообщение о временной недоступности; ручное сохранение остаётся доступно.
- Модель получает только извлечённый публичный текст, без cookies пользователя; store:false.
- Модель инструктируется не выдумывать факты и игнорировать инструкции внутри сайта. Результат всё равно требует проверки владельцем.

Проверки
npx tsx --test src/lib/website/website.test.ts
npx tsc --noEmit
npm run build

Для проверки в Supabase после настройки:
- Войти тестовым пользователем с компанией, проанализировать известный публичный сайт.
- Сверить услуги/цены/телефон с источниками, отредактировать и сохранить. Обновить страницу.
- Повторить анализ в течение минуты: должен вернуться 429 без вызова AI.
- Проверить выход из аккаунта: анализ должен отправить на /login.
- Убедиться, что отмена анализа и ошибки не изменяют сохранённый текст.
